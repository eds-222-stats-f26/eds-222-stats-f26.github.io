Scenarios

We do: nitrate in drinking water wells

Fertilizer and manure from farms leach nitrate into groundwater, and many rural communities in California’s Central Valley drink from wells. Nitrate above 10 mg/L (the drinking water standard) is a health risk, especially for infants. If agriculture is a source, wells surrounded by more farmland should have more nitrate.

  • x: farmland within 1 km of the well (%)
  • y: nitrate in well water (mg/L)
  • \(\beta_1\): change in nitrate per additional percentage point of farmland

You do: tree canopy and surface temperature

Pavement and rooftops soak up summer sun, making cities hotter than their surroundings. Trees shade the ground and cool the air through evapotranspiration. If tree canopy cools neighborhoods, then neighborhoods with more canopy should have lower summer surface temperatures.

A city measures tree canopy and the average July land surface temperature in 40 neighborhoods.

  • x: tree canopy cover (%)
  • y: July land surface temperature (°C)
  • \(\beta_1\): change in surface temperature per additional percentage point of canopy
How it works

Both scenarios use the same model:

\[ y = \beta_0 + \beta_1 x + \varepsilon, \quad \varepsilon \sim Normal(0, \sigma) \]

\(\beta_1\) is the quantity we care about. In both scenarios, the question is whether x is related to y: \(H_0: \beta_1 = 0\) versus \(H_A: \beta_1 \neq 0\). We can’t observe \(\beta_1\) directly. We only get a sample and an estimate, \(\hat\beta_1\). Inference is about using one sample to say how far \(\hat\beta_1\) might be from \(\beta_1\) and whether the data are consistent with \(\beta_1 = 0\).

Setup

We do

Population parameters

# Nitrate (mg/L) with no farmland
wells_beta_0 <- 4
# Additional nitrate per percentage point of farmland (mg/L per %)
wells_beta_1 <- 0.035
# Residual standard deviation (mg/L)
wells_sigma <- 2
How it works

These are the “truth” that we normally never get to see. A well with no farmland nearby averages 4 mg/L of nitrate. Each additional percentage point of farmland adds 0.035 mg/L, so a well surrounded by 80% farmland averages \(4 + 0.035 \times 80 = 6.8\) mg/L. That’s still below the 10 mg/L standard on average. But with \(\sigma = 2\) mg/L, individual wells scatter widely around that average, and some will exceed the standard.

Simulated population of wells

ag_pct <- runif(1e4, 0, 80)
nitrate_hat <- wells_beta_0 + wells_beta_1 * ag_pct
nitrate <- rnorm(1e4, nitrate_hat, wells_sigma)
simulated_population <- tibble(ag_pct, nitrate_hat, nitrate)
How it works

We simulate a population of 10,000 wells in three steps:

  1. Predictor. runif(1e4, 0, 80) gives each well a farmland percentage drawn uniformly between 0% and 80%.
  2. Expected value. nitrate_hat is the point on the population line for each well: \(\beta_0 + \beta_1 x\). This is the systematic part of the model.
  3. Response. rnorm(1e4, nitrate_hat, wells_sigma) adds normally distributed noise with standard deviation \(\sigma\) around each expected value. This is the \(\varepsilon\) part of the model, and it represents everything other than farmland that affects nitrate (soil type, well depth, irrigation practices, …).

Each well gets its own mean in rnorm(), because nitrate_hat is a vector of 10,000 values.

How it works

geom_abline() draws the population regression line using the true \(\beta_0\) and \(\beta_1\). The relationship is real but modest compared to the noise. Across the full range of farmland, the line rises less than 3 mg/L, while individual wells spread several mg/L above and below it. With this much noise, a small sample could easily give a misleading slope.

A water agency tests 30 wells

one_sample <- slice_sample(simulated_population, n = 30)
How it works

slice_sample() draws 30 rows at random, without replacement, from the population. This is the dataset a real agency would have: 30 wells, with no access to the other 9,970 or to the true parameters.

Run this chunk to simulate the data. In real life we wouldn’t know the population parameters, but here we can use them to check our inferences.

Part 1: p-value by permutation

We do

\(H_0\): \(\beta_1 = 0\)

\(H_A\): \(\beta_1 \ne 0\)

If \(H_0\) is true, then farmland has no relationship with nitrate, so shuffling farmland shouldn’t make a difference. Shuffle farmland 1000 times and re-fit the model to get the null distribution of \(\hat\beta_1\).

wells_permutations <- replicate(1e3, {
  permuted_sample <- one_sample |>
    mutate(ag_pct = sample(ag_pct))
  permuted_lm <- lm(nitrate ~ ag_pct, permuted_sample)
  permuted_beta_1_hat <- coef(permuted_lm)["ag_pct"]
  permuted_beta_1_hat
})
wells_null_distribution <- tibble(beta_1_hat = wells_permutations)
How it works

The logic. If \(H_0\) were true, which well had which farmland percentage would be irrelevant to its nitrate level. So we can reassign the farmland values at random and get a dataset that could just as plausibly have come from a world where \(H_0\) is true.

The code.

  • sample(ag_pct) with no other arguments returns the same 30 values in a random order. Every farmland value is still in the data and every nitrate value is still in the data. Only the pairing between them changes. Shuffling breaks any association between x and y while keeping each variable’s own distribution exactly the same.
  • We refit the model on the shuffled data and keep the slope.
  • replicate(1e3, { ... }) runs the code in braces 1,000 times and collects the last value from each run into a vector. Here that’s the 1,000 slopes.
  • We put the vector in a tibble so it’s easy to plot with ggplot.

The result is the null distribution: the slopes we’d expect to see from samples like ours if farmland had no effect on nitrate.

Compare the null distribution to the observed \(\hat\beta_1\). Shade the regions at least as extreme as the observed \(\hat\beta_1\) (in either direction, because \(H_A\) is two-sided).

`stat_bin()` using `bins = 30`. Pick better value `binwidth`.
# The p-value is the proportion of the null distribution at least as extreme as
# the observed beta_1_hat (i.e., in the shaded regions)
How it works

The null distribution is centered on 0, as it should be. Shuffling destroys the relationship, so the slopes average out to nothing.

The two annotate("rect", ...) layers shade the tails:

  • The left rectangle runs from -Inf to -abs(wells_beta_1_hat).
  • The right rectangle runs from abs(wells_beta_1_hat) to Inf.

Using abs() means the shading is correct whether \(\hat\beta_1\) is positive or negative. We shade both tails because \(H_A: \beta_1 \neq 0\) is two-sided. Before seeing the data, a large negative slope would have been just as much evidence against \(H_0\) as a large positive one.

ymin = -Inf, ymax = Inf stretches the rectangles to the full height of the plot.

The p-value is the proportion of the null distribution at least as extreme as the observed \(\hat\beta_1\)

mean(abs(wells_null_distribution$beta_1_hat) >= abs(wells_beta_1_hat))
[1] 0.015
How it works

abs(wells_null_distribution$beta_1_hat) >= abs(wells_beta_1_hat) is a logical vector with one TRUE/FALSE per permutation. TRUE means that permuted slope was at least as far from 0 as the slope we observed. Taking the mean() of a logical vector gives the proportion of TRUEs, because R treats TRUE as 1 and FALSE as 0.

Interpretation: if farmland had no relationship with nitrate, only about 1.5% of samples would show a slope at least as far from 0 as ours, in either direction. That’s below 0.05, so we reject \(H_0\). The data are hard to explain without some relationship between farmland and nitrate.

With 1,000 permutations, the p-value can only take values in steps of 0.001, and it would change slightly with a different seed. More permutations would make it more precise.

You do

\(H_0\): \(\beta_1 = 0\)

\(H_A\): \(\beta_1 \ne 0\)

If \(H_0\) is true, shuffling canopy across neighborhoods shouldn’t make a difference. Shuffle canopy_pct 1,000 times, refitting the model each time, to build the null distribution of \(\hat \beta_1\).

permutations <- replicate(1e3, {
  permuted_sample <- neighborhoods |>
    mutate(canopy_pct = sample(canopy_pct))
  permuted_lm <- lm(surface_temp ~ canopy_pct, data = permuted_sample)
  coef(permuted_lm)["canopy_pct"]
})
null_distribution <- tibble(beta_1_hat = permutations)
Solution
  • sample(canopy_pct) shuffles the canopy values among the neighborhoods. This breaks the link between canopy and temperature, which is exactly what \(H_0\) says doesn’t exist.
  • The model is fit to permuted_sample, the shuffled data. A common mistake is to write data = neighborhoods here. That refits the original data 1,000 times and gives the same slope every time.
  • coef(permuted_lm)["canopy_pct"] is the last line in the braces, so it’s the value replicate() collects from each run.

Solution

The left tail runs from -Inf to -abs(beta_1_hat), and the right tail runs from abs(beta_1_hat) to Inf. Here \(\hat\beta_1\) is negative, so the solid line sits in the left shaded region. The right shaded region is its mirror image. We still count it because the test is two-sided.

Compared to the wells, the observed slope sits much closer to the edge of the null distribution. It’s in the tail, but not far out in it.

Calculate the p-value: the proportion of the null distribution at least as extreme as the observed \(\hat \beta_1\).

perm_pvalue <- mean(abs(null_distribution$beta_1_hat) >= abs(beta_1_hat))
perm_pvalue
[1] 0.047
Solution

Both blanks are abs. Comparing absolute values counts permuted slopes that are extreme in either direction, which matches the two-sided \(H_A\). If you left out abs(), you’d count every permuted slope above a negative number, which would be almost all of them. That gives a p-value near 1, and the result is meaningless.

Interpret the p-value in one sentence. Do you reject \(H_0\)?

If tree canopy had no relationship with surface temperature, we would see a slope at least as far from 0 as the observed \(\hat \beta_1\) in about 4.7% of samples. p < 0.05, so we reject \(H_0\).

Solution

A good interpretation has three parts:

  1. The assumption: if \(H_0\) were true (no relationship).
  2. What the p-value is a proportion of: samples with a slope at least as extreme as ours, in either direction (at least as far from 0).
  3. The decision: compare to \(\alpha = 0.05\).

Common mistakes:

  • “There’s a 4.7% chance that \(H_0\) is true.” This is wrong. The p-value is computed assuming \(H_0\) is true, so it can’t be the probability that \(H_0\) is true.
  • “We accept \(H_0\).” We never accept \(H_0\). If p ≥ 0.05, we fail to reject. The data just aren’t strong enough evidence against it.

Here p = 0.047, which is right at the edge of the 0.05 threshold. Keep that in mind when you compare it to lm() in Part 2.

Part 2: p-value by mathematical model

We do

Compare the permutation p-value to lm()’s Pr(>|t|)

# Using the permutation test
mean(abs(wells_null_distribution$beta_1_hat) >= abs(wells_beta_1_hat))
[1] 0.015
# Using lm()
summary(one_sample_lm)$coefficients["ag_pct", "Pr(>|t|)"]
[1] 0.02423736
How it works

summary(one_sample_lm)$coefficients is a matrix with one row per coefficient and four columns: Estimate, Std. Error, t value, and Pr(>|t|). We index it as [row, column] by name.

lm() doesn’t shuffle anything. It uses a mathematical shortcut instead:

  1. Compute the t statistic: \(t = \hat\beta_1 / SE(\hat\beta_1)\), or how many standard errors the estimate is from 0.
  2. If \(H_0\) is true and the model’s assumptions hold (linear relationship, independent observations, normal residuals with constant variance), \(t\) follows a t distribution with \(n - 2\) degrees of freedom.
  3. Pr(>|t|) is the area in both tails of that t distribution beyond \(|t|\).

So the t distribution plays the same role as our permutation null distribution. One is derived from theory and the other is built by simulation.

The two p-values (0.015 and 0.024) are similar, and both are below 0.05. They aren’t identical because the permutation test has simulation noise and the t-test relies on distributional assumptions. When the assumptions are reasonable, the two methods should agree closely.

Solution

The blank is the column name "Pr(>|t|)", typed exactly as it appears in the coefficients table, inside quotes. coef(summary(canopy_lm)) is equivalent to summary(canopy_lm)$coefficients.

You can check this against the t statistic by hand. \(t =\) -0.0536 / 0.0274 = -1.96, and 2 * pt(-abs(t), df = 38) gives the same p-value.

How do the permutation and lm() p-values compare? Do they lead to the same conclusion?

The two p-values are similar (0.047 from the permutation test and 0.057 from lm()). But they fall on opposite sides of 0.05, so they lead to different conclusions: the permutation test says reject and lm() says fail to reject. The evidence against \(H_0\) is borderline either way.

Solution

This is a useful case to think about. The two methods disagree on the decision, even though the p-values themselves are close. A few points to take from this:

  • Similar p-values are what we expect. The permutation test and the t-test answer the same question with different machinery, so they should land in the same neighborhood. A difference of about 0.01 is typical, given simulation noise from 1,000 permutations plus the t-test’s assumptions.
  • The 0.05 threshold is a convention, not a law of nature. Two p-values this close (0.047 and 0.057) carry nearly the same amount of evidence. Treating one as a “discovery” and the other as “nothing” is a common misuse of hypothesis testing. Report the p-value itself, not just “significant” or “not significant.”
  • Remember the truth. We know the true \(\beta_1 =\) -0.01, so \(H_0\) is actually false. But the true effect is tiny relative to \(\sigma\), and 40 neighborhoods isn’t enough to detect it reliably. That’s what low statistical power looks like. Failing to reject \(H_0\) doesn’t mean there’s no effect.

Part 3: confidence interval by bootstrap

We do

Treat the sample as a stand-in for the population. Resample it with replacement 1000 times and re-fit the model to approximate the sampling distribution of \(\hat\beta_1\).

boot_betas <- tibble()
for (i in 1:1000) {
  boot_sample <- slice_sample(one_sample, n = nrow(one_sample), replace = TRUE)
  boot_lm <- lm(nitrate ~ ag_pct, boot_sample)
  boot_beta_1_hat <- coef(boot_lm)["ag_pct"]
  resampled_betas <- tibble(
    beta_1_hat = boot_beta_1_hat,
    iteration = i
  )
  boot_betas <- rbind(boot_betas, resampled_betas)
}
How it works

The logic. A confidence interval should reflect how much \(\hat\beta_1\) would vary if we could draw many samples from the population. We can’t do that, because we only have one sample. The bootstrap’s trick is to treat the sample as if it were the population and draw new samples from it.

Why with replacement? Each bootstrap sample has the same size as the original (n = nrow(one_sample), here 30). If we sampled 30 out of 30 without replacement, we’d get the exact same wells every time, just in a different order, and the same slope. Sampling with replacement means some wells show up two or three times and others don’t show up at all. That creates realistic variation between bootstrap samples.

Permutation vs. bootstrap. Both resample, but in different ways for different purposes:

Permutation (Part 1) Bootstrap (Part 3)
What’s resampled Shuffle x only Resample whole rows (x and y together)
Relationship between x and y Destroyed Preserved
Distribution is centered on 0 \(\hat\beta_1\)
Used for p-value (testing \(H_0\)) Confidence interval (estimating \(\beta_1\))

The code. This version uses a for loop instead of replicate() so you can see each step. Each iteration builds a one-row tibble and rbind()s it onto boot_betas. It also records the iteration number, which can be handy for debugging. replicate() (as in the You do) is shorter and faster, and it gives the same result.

The middle 95% of the bootstrap distribution is the 95% confidence interval. Shade it on the bootstrap distribution, and compare to the observed \(\hat\beta_1\) (solid) and the true \(\beta_1\) (dashed).

  ) +
  geom_vline(
    xintercept = wells_beta_1_hat,
    color = "firebrick",
    linewidth = 1.5
  ) +
  geom_vline(
    xintercept = wells_beta_1,
    color = "firebrick",
    linewidth = 1.5,
    linetype = "dashed"
  )
`stat_bin()` using `bins = 30`. Pick better value `binwidth`.
# The bootstrap distribution is centered on beta_1_hat, not beta_1!
How it works

quantile(x, c(0.025, 0.975)) returns the 2.5th and 97.5th percentiles, so the middle 95% of the bootstrap slopes falls between them. This is the percentile bootstrap confidence interval: (0.0055, 0.0694) mg/L per %.

Notice where the histogram is centered. It’s centered on \(\hat\beta_1\) (solid line), not on the true \(\beta_1\) (dashed line). The bootstrap can’t know the truth, because it only knows our sample. What it gets right is the spread. The bootstrap distribution’s width approximates the width of the true sampling distribution, and that’s all we need for a confidence interval.

Interpretation: we are 95% confident that each additional percentage point of farmland is associated with between 0.006 and 0.069 mg/L more nitrate. The interval contains the true \(\beta_1 =\) 0.035. It also doesn’t contain 0, which matches our Part 1 decision to reject \(H_0\). A 95% CI that excludes 0 corresponds to a two-sided test that rejects at \(\alpha = 0.05\).

“95% confident” refers to the procedure. If we repeated this whole process (draw a sample, bootstrap, build the interval) many times, about 95% of the intervals would contain the true \(\beta_1\). Any single interval either contains \(\beta_1\) or it doesn’t.

You do

How much does surface temperature change per percentage point of canopy? Resample the neighborhoods with replacement 1,000 times, refitting the model each time, to approximate the sampling distribution of \(\hat \beta_1\).

bootstraps <- replicate(1e3, {
  boot_sample <- slice_sample(
    neighborhoods,
    n = nrow(neighborhoods),
    replace = TRUE
  )
  boot_lm <- lm(surface_temp ~ canopy_pct, data = boot_sample)
  coef(boot_lm)["canopy_pct"]
})
boot_distribution <- tibble(beta_1_hat = bootstraps)
Solution
  • n = nrow(neighborhoods): each bootstrap sample is the same size as the original, 40 neighborhoods. Writing n = 40 works too, but nrow() keeps working if the data change.
  • replace = TRUE: this is what makes it a bootstrap. With replace = FALSE, every “resample” would contain the same 40 neighborhoods, and all 1,000 slopes would be identical.
  • lm(surface_temp ~ canopy_pct, data = boot_sample): fit the same model as before, but to the resampled data.

Unlike the permutation test, we resample whole rows. Each neighborhood’s canopy and temperature stay together, so the relationship between them is preserved.

Two more things to notice:

  • Does it contain 0? The interval does contain 0. So a slope of zero (no cooling effect) is among the plausible values, which is consistent with failing to reject \(H_0\).   • The interval is wide. It runs from a fairly strong cooling effect (-6.3 °C across 0–60% canopy) to slight warming (0.2 °C). With 40 noisy neighborhoods, the data can’t pin down \(\beta_1\) precisely. A wide interval is an honest statement of that uncertainty.

Part 4: confidence interval by mathematical model

We do

Compare the bootstrap and confint() confidence intervals

# Using the bootstrap
wells_boot_ci
       2.5%       97.5% 
0.005510565 0.069356957 
# Using confint()
confint(one_sample_lm)["ag_pct", ]
      2.5 %      97.5 % 
0.005219117 0.069263593
How it works

confint() builds the interval from a formula instead of resampling:

\[ \hat\beta_1 \pm t^*_{n-2} \times SE(\hat\beta_1) \]

\(t^*_{n-2}\) is the 97.5th percentile of a t distribution with \(n - 2\) degrees of freedom, qt(0.975, df = 28) \(\approx\) 2.05 for 30 wells. confint() returns a matrix with one row per coefficient, so ["ag_pct", ] picks the slope row and both columns.

The two intervals are very close. As with the p-values in Part 2, the simulation method and the formula agree when the model’s assumptions are reasonable. One difference is that the formula interval is always symmetric around \(\hat\beta_1\), while the bootstrap interval can be lopsided if the sampling distribution is skewed.

The standard deviation of the bootstrap distribution approximates the standard error

# Using the bootstrap
sd(boot_betas$beta_1_hat)
[1] 0.01639129
# Using lm()
summary(one_sample_lm)$coefficients["ag_pct", "Std. Error"]
[1] 0.01563275
How it works

The standard error is, by definition, the standard deviation of the sampling distribution of \(\hat\beta_1\). The bootstrap distribution approximates the sampling distribution, so its standard deviation approximates the standard error. lm() calculates the same quantity from a formula based on \(\hat\sigma\), \(n\), and the spread of x. The two numbers (0.0164 and 0.0156) are nearly identical.

This ties the lab together. The standard error is the key quantity behind both the t statistic (Part 2) and the confidence interval (Part 4).

Big picture: for both scenarios, we answered the same two questions in two ways.

Question Simulation Mathematical model
Is the data consistent with \(\beta_1 = 0\)? Permutation test t-test (lm() p-value)
What values of \(\beta_1\) are plausible? Bootstrap CI confint()

The simulation methods make the logic visible. The mathematical methods are faster and are what you’ll usually see reported. When the model’s assumptions hold, they give nearly the same answers.
